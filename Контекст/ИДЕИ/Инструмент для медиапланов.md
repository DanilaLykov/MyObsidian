
## Идея

- Ускорить/упростить создание медиапланов 
- Систематизировать хранение медиапланов
- Избавиться от двойного внесения данных для контроля расходов 
- Возможность контроля расходов по рекламным кампаниям, а не по аккаунтам
- В идеале - автоматическая перенастройка бюджета в РК в соотв. с медиапланом
- Автоматизировать процесс заполнения ячеек прогнозов



Важные моменты:

- Чтобы механизм работал, каждая РК (строчка в медиаплане) должна быть связана с РК в Директе

## Вопросы

- Как поступать с новыми РК, которых еще нет в директе
- Как прикреплять РК к строкам в медиаплане
- Как прикреплять аккаунт к медиаплану (Сущность)
- Как хранить медиапланы в базе


## Сущность Клиента

- Название * (вводится вручную, либо берется из директа)
- Логин Яндекс.Директ (вводим или берем с Дриекта)
- Адрес сайта

Новая сущность может появиться при обновлении данных о клиентах из Директа, либо может быть создана вручную. 


## Сущность  строки в медиаплане

- Название РК  (Строка)
- Описание РК (Многострочное поле)
- Форматы объявлений (Мультиселект из фиксированного списка)
- Место показа (Мультиселект)
- Таргетинг (Многострочное поле)
- Регионы (Многострочное поле)
- Стратегия (Мультиселект) ( я за многостр.)
- Бюджет (Целое число)

## Прогноз для ==новых== рекламных кампаний

Все расчеты отталкиваются от прогноза бюджета в Я.Директ.

Для поисковых РК

- Показы - из прогноза
- Стоимость клика - из прогноза
- Количество кликов - из прогноза
- CTR - из прогноза

Для РСЯ все данные рассчитываются исходя из некоторых коэффициентов по сравнению с поисковыми системами. 
- Коэффициент стоимости клика из РСЯ ~10
- Средний CTR из РСЯ
- Коэффициент различий по кликам при одновременной рекламе в РСЯ и Поиске

Остальные данные рассчитываются исходя из этих параметров.
